# AppWatcher alpha.21 信頼性改善 実装報告

検証日：2026-09-20

## 対象と結果

`C:\work\codex\projects\AppWatcher` の `feature/initial-implementation` ブランチで、`0b39118`（alpha.20）を基準に信頼性改善を実装し、バージョンを `0.1.0-alpha.21` に更新した。実装と自動検証・配布物検証は完了。隔離Windows環境での実UI・権限連携確認は未実施のため、beta移行の判断には追加の手動確認が必要。

## 主な変更

- 監視対象をID単位で差分更新し、手動Stop、個別Pause期限、再起動履歴、Backoff、追跡中プロセスを保持する。
- Stopの意図と表示状態を分離し、Resumeやメンテナンス解除、古いタイマー・終了イベントによる意図しない起動を防止する。非同期処理をキャンセルして終了待ちする。
- 実行ファイル・権限変更前に停止を要求し、停止後の権限移管でも明示Startを待つ。トレイとダッシュボードの両ホスト操作を共通化し、片側失敗を表示する。
- 設定処理をファイルロックでプロセス間排他し、最新設定への部分更新、一意な一時ファイル、置換保存、バックアップ保護を実装する。
- DB障害でも監視とIPCを開始・継続し、ログを非同期の有限キューへ分離する。DB再試行は1分間隔に制限する。
- 共通の引数マスキングを導入し、診断DBをマスク済み行から新規作成する。DB取得失敗時の生ファイルコピーを廃止する。
- 起動時・毎時の保持期限／容量整理と、fallbackログの5 MiB・旧2世代ローテーションを実装する。
- テスト用プロセス・時刻・保存先を分離し、配布物のテスト関連ファイル・ユーザーデータ混入検査を強化する。

## 未実施と運用上の注意

- 隔離WindowsユーザーまたはVMによる実UI、通常権限／管理者権限、UAC、Task Scheduler、ログオフ／シャットダウンの組合せ検証は未実施。自動テストによる代替完了とは扱わない。
- 常駐時のCPU・メモリ等の変更前後の実測は未実施。
- ログ容量は毎時整理による目標値であり、DB本体やWALは一時的に超過し得る。ロック競合時は縮小・整理を延期する。
- ログキューは有限であり、保存遅延が続く場合は欠落件数をfallbackへ記録する。
- 秘密情報除去はpassword、passwd、token、api-key、api_key、secretの対応する引数形式が対象。任意形式の秘密情報の完全除去は保証しない。過去の実運用DBは書き換えない。
- 稼働中のAppWatcher、監視対象、実運用設定・DB・タスク登録は変更していない。既存Agent／Elevatedの同じPIDが引き続き存在することを確認した。
- push、タグ作成、Release公開、実運用への差し替えは実施していない。UI高速化、通知追加、HTTP/TCP監視、永続Pauseは対象外。
